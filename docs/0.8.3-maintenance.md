# VAV 0.8.3 — maintenance en cours

## Audit initial (base 4cab89a, v0.8.2)

- React 19 / TypeScript 5.9 / Vite 7, Tauri 2, Rust 2021, rusqlite 0.37 avec SQLite embarqué et API backup ; reqwest 0.12 ; updater Tauri 2.13.1 (lockfile).
- SQLite : database.sqlite dans app_data_dir, identifiant local.vrc-avatar-vault.app commun portable/installé. Migrations SQL 001–003, user_version 3. Transaction déjà présente, pas de reset automatique.
- Backups : API SQLite incluant WAL. Quick-check avant migrations/installations, mais sauvegarde manuelle non vérifiée ; pas de rétention ; contrôles dupliqués.
- Restore : JSON validé côté frontend puis transaction SQL ; sauvegarde préalable, images renommées. Pas de remplacement physique de la base ouverte. Conservation de cette architecture.
- Updater : plugin officiel vérifiant Minisign, SemVer ; verrou asynchrone ; téléchargement en mémoire (aucun .tmp persistant), mais pas de SHA-256 du manifeste. Updater local : taille et SHA-256, sans signature dans le format historique.
- Logs : événements API fixes seulement, debug facultatif, rotation limitée. Pas de diagnostic exportable. ErrorBoundary React présent ; erreur DB dans setup fait échouer le démarrage natif.
- Auth : cookies dans coffre système, erreurs HTTP distinctes, backoff ; surveillance frontend avec timer nettoyé et verrou, requêtes sérialisées.
- OSC : localhost, timeout de lecture et arrêt/join. API locale : localhost et token, mais thread non joint lors de Stop (redémarrage immédiat susceptible de conflit).
- Paramètres SQLite ; exports de fichiers écrits directement. Installateur NSIS currentUser, même identifiant AppData, suppression explicite seulement.
- Scripts version/package existants ; build local disponible. Actions : hors périmètre facturation.
- Référence tests 0.8.2 : 71 frontend + 26 Rust + 3 Discord.

## Vérification à compléter

Les matrices installateur/portable, connexion VRChat réelle et Unity ne sont pas encore exécutées pour 0.8.3. Ne pas annoncer la release terminée avant validation. Aucun accès aux données personnelles nécessaire aux tests de migration.

## Corrections implémentées

- Backup central avec header, intégrité complète et clés étrangères ; sauvegardes autonomes (journal DELETE). Rétention des seules nouvelles copies auto-verified : 20. Les anciens backups/manuels ne sont pas supprimés.
- Restore JSON sous un seul verrou SQLite : backup vérifié, transaction, intégrité, commit ou rollback. Images ajoutées sous des noms uniques ; un échec peut laisser une image orpheline mais ne supprime pas les anciennes.
- Base au header invalide refusée ; écran de récupération avant chargement du workspace. Pas de reset, pas de scan complet systématique à chaque lancement.
- Download GitHub en fichier temporaire borné à 200 Mio ; contrôle taille/hash/signature et version signée, revérification avant installation. Seuls les octets vérifiés en mémoire sont installables. .tmp abandonnés de plus d’une heure nettoyés au démarrage ; les plus récents sont ignorés pour protéger une autre instance.
- Updater local : signature liée à la version obligatoire pour les paquets >= 0.8.3. Le générateur local produit aussi latest.json compatible Tauri, enrichi de size/sha256. Le workflow cloud est adapté statiquement.
- Logs INFO/WARN/ERROR/DEBUG, rotation 1 Mio + 3 archives ; événements sensibles entièrement masqués, chemins utilisateur normalisés. Export support limité aux diagnostics et aux 4 nouveaux journaux, 32 K caractères assainis par fichier. Pas d’export des anciens journaux, des settings ni de la base.
- Diagnostics disponibles à la demande : intégrité, schéma, version/OS/architecture, chemins normalisés, dernier résultat updater, état API locale. Aucun appel VRChat depuis ce panneau ; statut de connexion à consulter dans Account.
- Annulation des rafraîchissements en file après logout, effacement de l’état connecté après 401, délai Retry-After mémorisé au backend.
- API locale : arrêt rejoint le thread et deadline globale de lecture (évite un client qui bloque indéfiniment le redémarrage). OSC existant conserve son arrêt/join et son test loopback.
- Export atomique, gestion générique des promesses non traitées, ErrorBoundary sans détails sensibles et ouverture des logs. Confirmation d’abandon du formulaire de release.
